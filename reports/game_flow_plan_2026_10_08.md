# 게임 흐름 계획 — 타이틀부터 스테이지까지 (2026-10-08)

지금은 실행하면 곧바로 축제 거리 한복판에 서 있다. 그 앞뒤로 **타이틀 → (튜토리얼) → 모집맵 → 트럭 → 스테이지**를 붙이는 것이 이 문서의 대상이다.

이 문서는 계획이고, 아직 아무것도 구현되지 않았다. 여기 적힌 "지금 구조"는 2026-10-08 `tutorial` 브랜치 기준으로 코드를 읽고 확인한 것이다.

---

## 1. 목표 흐름

```
타이틀 화면 "Sauce IT!"
  └ 메뉴: 게임시작 / 옵션 / …
      └ 게임시작
          ├ 첫 플레이      → 튜토리얼 ──(클리어 시 자동)──┐
          └ 해본 적 있음   ───────────────────────────────┴→ 모집맵
                                                              │
                        사무실 형태의 작은 방. 1인칭으로 돌아다님    │
                        (조작은 본편과 동일)                      │
                        큰 스크린에 다가가 상호작용               │
                                                              ↓
                                                   모집 페이지 (UI)
                                              서버 만들기 / 서버 참여하기
                                                              ↓
                                                      트럭 안 (로비)
                                        군용 트럭처럼 양쪽 벤치
                                        한 명 들어올 때마다 한 자리씩 참
                                                              ↓
                                   방장이 "시작하기" → 전원 동시 입장
                                                              ↓
                                      방 만들 때 고른 스테이지 맵
                                            플레이 → 클리어
```

### 장소는 네 종류

| 장소 | 성격 | 세션 상태 |
|---|---|---|
| **튜토리얼** | 1회성. 처음 플레이할 때만 | 혼자 |
| **모집맵** | 사무실 작은 방. 허브. 스크린이 메뉴 역할 | 혼자 |
| **트럭** | 로비. 들어온 인원이 벤치 자리로 보임 | 세션 열림 (방장 = 서버) |
| **스테이지** | 실제 플레이. 방 만들 때 선택 | 세션 유지 |

### 스테이지는 서로 연결되지 않는다

마리오식 개별 스테이지다. 한 장소에서 다른 장소로 걸어가는 것이 아니라, 방을 만들 때 고르고, 클리어하면 끝난다. **따라서 스테이지 간 이동·연속성·진행도 저장 같은 시스템은 필요 없다.** 필요한 것은 "어느 장소를 지을지 고르는 것" 하나다.

## 2. 지금 구조

### 게임 = 씬 하나

`project.godot`의 `run/main_scene`이 `main.tscn`이고, 그 루트의 `MayoPrototype`(`scripts/mayo_prototype.gd`, 5,400줄)이 `_ready()`에서 거리를 짓고, 플레이어를 만들고, 적을 깔고, HUD를 붙인다. 화면 흐름이라는 개념이 없다. 타이틀도, 씬 전환도, 그것을 관리하는 것도 없다.

### 튜토리얼은 별도 맵이 아니다

같은 거리 위에서 돈다. `_build_tutorial()`이 켜지면 그 거리를 고쳐 쓴다:

- 거리 아래쪽 Kalda 근처에 부서진 수레 더미(`TutorialWreck`, `CENTRE_Z = -7.5 * CELL`)를 놓고
- 매대 하나를 지우고(`TutorialWreck.replaces_stall`), 하드코딩된 `Vector3(8, 2.8, -6)`에 튜토리얼 전용 소스 매대를 세우고
- 거리의 상주 적 로스터를 통째로 막는다 (`_build_enemies`가 튜토리얼이면 빈 채로 반환)

**즉 "튜토리얼 맵"과 "축제 맵"은 같은 맵이다.** `tutorial_enabled`를 끄면 수레 더미도 전용 매대도 없고, 매대가 전부 서 있고, 상주 적이 깔린 깨끗한 축제 거리가 나온다. → **1번 축제는 이미 존재한다. 새로 만들 것이 아니라 이름을 붙이면 되는 상태다.**

### 맵 코드는 "설계도"와 "건설 기계"로 갈려 있다

`scripts/street_map.gd` 653줄 중,

**설계도 — 이 장소에만 해당하는 데이터:**

| 항목 | 개수 |
|---|---|
| `SEGMENTS` (거리 네모) | 6 |
| `CIRCLES` (둥근 장소) | 1 |
| `STALL_ANCHORS` (매대 좌표) | **51** |
| `DOUBLE_BAY_MARKERS` (2칸 매대) | 11 |
| `VENDING_ANCHORS` | 2 |
| 무대 / 타워 위치 | 2 |
| `SCALE`, `WALL_HEIGHT`, `PX_PER_CELL`, `ORIGIN_CELL` | 4 |

매대 51개는 하파살루 축제 지도 그림의 빨간 번호 마커를 픽셀로 하나씩 딴 것이다 (`[299, 190], [340, 172], …`).

**건설 기계 — 장소를 가리지 않는 알고리즘 (~500줄):** 벽 병합, 매대 전면 배치, 격자↔월드 변환, 네비 셀 계산. 설계도가 뭐가 되든 똑같이 돈다.

### 단, 건설 기계는 "거리형 축제"를 전제한다

아무 장소나 지어주지는 않는다. 깔고 있는 전제가 있다:

- 길은 8칸 폭 네모들의 합집합이다 (`ROAD_CELLS = 8`)
- **벽은 자동 생성된다** — 길이 아니면서 길에 붙은 칸을 전부 벽으로 세운다. 기본형이 "양옆 막힌 골목"이다
- **바닥은 평평한 판 하나다** — `floor_plane()`이 높이 하나짜리 평면을 돌려준다. 경사도 층도 없다
- **매대는 길가에 자동으로 붙는다** — 좌표만 주면 가장 가까운 길을 찾아 전면을 길 쪽으로 돌린다

| 만들고 싶은 장소 | 지금 기계로 되나 |
|---|---|
| 다른 모양의 거리 축제 | ✅ 설계도 데이터만 |
| 넓은 광장 하나 | ✅ 네모 하나 크게 |
| **사무실 작은 방 (모집맵)** | ❌ 실내. 천장 개념 없음 |
| **트럭 안 (로비)** | ❌ 실내. 거리형이 아님 |
| 해변·공원 (벽 없는 열린 공간) | ❌ 길 경계가 곧 벽 |
| 언덕·계단·2층 | ❌ 바닥이 평면 하나 |

→ **모집맵과 트럭은 `StreetMap` 경로로 지을 수 없다.** 손으로 만든 씬이어야 한다. 다행히 둘 다 작고 고정된 공간이라 절차적 생성이 필요 없다.

## 3. 이미 있는 것 / 없는 것

### 이미 있는 것 — 제일 어려운 부분이 이미 됐다

- **네트워크 코어** (`scripts/net_game.gd`) — 호스트/참여, 로비 코드 인증, 접속·이탈 처리, 슬롯 배정(`MAX_CLIENTS = 3`, 즉 최대 4인), 서버 권위 상태 동기화, 늦게 들어온 피어에게 현재 마스크 넘겨주기. 멀티에서 제일 골치 아픈 부분이다.
- **접속 UI** (`scripts/net_panel.gd`) — 호스트/참여 폼. 파일 주석에 범위가 명시돼 있다: *"No lobby, no player list, no matchmaking."* 모자란 것이 정확히 그 셋이다.
- **1인칭 조작 + 상호작용** — 모집맵에서 스크린에 다가가 누르는 것은, 지금 매대에서 `E`로 소스를 받는 것과 같은 패턴이다.
- **튜토리얼 레슨 흐름** (`scripts/tutorial.gd`) — `Stage` 11단계가 이미 서 있다. 소스 받기 → 첫 전투 → 몬스터 추격 → 미끄러짐/달리기 → 보급 → 협동 전투 → 아웃트로.

### 없는 것

| | 지금 상태 |
|---|---|
| **화면 흐름** | 없음. `main.tscn`이 곧 게임. 전환을 관리하는 것이 없음 |
| **저장** | 없음. `user://`에 쓰는 코드가 하나도 없다 (`scale_test_base.gd`의 테스트 스크린샷 저장 제외). 튜토리얼 완료 여부를 적어둘 곳이 없음 |
| **맵 선택** | 없음. 코드가 `StreetMap`의 static을 직접 부른다 |
| **로비** | 없음. 인원 목록이라는 개념 자체가 없음 |
| **동시 입장** | 없음. 전원을 같은 순간에 스테이지로 보내는 절차 |

## 4. 핵심 전환

지금: **"게임 = 씬 하나"**
목표: **"껍데기가 장소를 갈아끼운다"**

이 뒤집기가 본체이고, 나머지 작업은 전부 여기 매달린다. `MayoPrototype`이 "유일한 세계"에서 "껍데기가 띄우는 여러 장소 중 하나"로 내려와야 한다.

### 세션 경계 — 리슨 서버라서 생기는 문제

장소마다 세션 상태가 다르다:

- **모집맵** = 아직 혼자. 세션 없음
- **트럭** = 세션 열린 상태. 방장이 서버
- **스테이지** = 세션을 **유지한 채** 장소만 교체

지금은 세션이 열리고 닫히는 일이 "게임 도중"에만 일어난다. **장소를 건너가면서 세션을 유지해야 하는 것은 새 요구사항이다.** 트럭에서 스테이지로 갈 때 연결이 끊기면 안 되고, 전원이 같은 스테이지를 같은 순간에 지어야 한다.

## 5. 작업 덩어리

크기는 거친 어림이다. 순서는 6장에 따로 적는다.

| 덩어리 | 크기 | 내용 |
|---|---|---|
| **씬 흐름 껍데기** | **큼** | 장소를 띄우고 내리는 관리자. 타이틀·튜토리얼·모집맵·트럭·스테이지가 전부 여기 매달린다 |
| 저장 | 작음 | `user://`에 설정 파일. 튜토리얼 완료 플래그, 나중에 옵션도 |
| 타이틀 화면 + 메뉴 | 작음 | "Sauce IT!", 게임시작/옵션 |
| 맵 선택 | 중간 | 설계도를 고를 수 있게. 자세한 것은 아래 |
| 모집맵 | 중간 | 사무실 씬(수작업) + 스크린 상호작용. 조작은 재사용 |
| 모집 페이지 UI | 작음~중간 | `net_panel` 확장. 맵 선택이 여기 붙는다 |
| 트럭 로비 | 중간 | 트럭 씬(수작업) + 인원 목록 동기화 + 벤치 자리 표시 |
| 동시 입장 | 작음~중간 | 네트워크 기반은 있음. "전원 같은 장소로" 절차 추가 |
| 튜토리얼을 자기 장소로 분리 | 중간 | 하드코딩된 수레·매대 좌표를 튜토리얼 설계도로. 프로브 6개가 따라옴 |

### 맵 선택을 어떻게 할 것인가

두 갈래가 있다.

**싼 길 (권장)** — `StreetMap`을 static으로 둔 채, 월드를 짓기 직전에 "이번엔 어느 설계도" 하고 한 번 정해주는 방식. 설계도 상수 15개만 그 장소에서 읽어오게 한다. **맵을 부르는 138군데를 하나도 건드리지 않는다** (그 대부분은 건설 기계를 부르는 쪽이라 설계도가 바뀌든 상관없다). 전역 가변 상태라 모양은 안 예쁘지만, 지금 코드가 이미 그 모양이고 프로브도 그대로 돈다.

**깨끗한 길** — 설계도를 객체로 만들어 인자로 돌린다. 호출부 전부를 건드린다.

장소가 2~3개 생겨서 실제로 무엇이 다른지 보인 뒤에 깨끗한 길로 가는 편이, 지금 추측으로 추상화하는 것보다 낫다.

## 6. 순서

한 번에 다 하면 중간에 아무것도 안 돌아가는 기간이 길어진다. **각 단계가 끝날 때마다 게임이 돌아가는 상태를 유지하는** 순서로 간다.

1. **씬 흐름 껍데기 + 타이틀**
   타이틀을 눌러서 지금 게임으로 들어가기만 한다. 그 외에는 지금과 동일. 가장 큰 덩어리를 가장 작은 결과물로 먼저 세운다.
2. **저장**
   튜토리얼 완료 플래그. 1번이 있어야 쓸 데가 생긴다.
3. **맵 선택 — 1번 축제 확정**
   지금 거리에 이름을 붙이고, 설계도를 고를 수 있게 한다.
4. **모집맵**
   지금 `F2` 패널을 스크린 뒤로 옮긴다. 이 시점에 모집 페이지 UI가 같이 간다.
5. **트럭 로비 + 동시 입장**
   인원 목록과 벤치. 세션을 유지한 채 스테이지로 넘기는 절차.
6. **튜토리얼 분리**
   마지막. 앞의 것들이 다 선 뒤여야 튜토리얼이 "자기 장소"를 가질 수 있다.

## 7. 아직 안 정해진 것

- **2번 스테이지가 어떤 장소인가.** 또 다른 거리 축제라면 설계도 데이터만으로 되고, 분위기가 다른 곳이라면 건설 기계까지 일이 번진다. 코드가 아니라 이 결정이 제일 큰 미지수다.
- **옵션 메뉴에 무엇이 들어가는가.** 저장 포맷이 여기 달려 있다.
- **모집맵·트럭을 어떻게 만드는가.** 둘 다 `StreetMap` 경로로는 못 짓는다. 손으로 만든 씬이 될 텐데, 작고 고정된 공간이라 절차적 생성은 필요 없다.
- **튜토리얼 전용 장소의 모양.** 지금은 축제 거리 아래쪽을 빌려 쓰고 있다.
- **클리어 조건.** "스테이지를 클리어한다"가 구체적으로 무엇인지 아직 없다.

## 8. 걸리는 것

- `probe_tutorial*` 6개가 "튜토리얼은 이 거리의 이 좌표에 있다"를 전제한다. 6단계에서 같이 옮겨야 한다. 큰일은 아니고 양이 있다.
- `MayoPrototype`이 5,400줄이고 자기가 유일한 세계라고 전제한다. 1단계의 위험이 전부 여기 몰려 있다.
- 매대 51개 같은 설계도 데이터는 **코드가 아니라 손품**이다. 참고할 그림이 있으면 따면 되고, 없으면 배치해야 한다.
